# Supabase ログイン・保存・同期の設定手順

このフォルダ専用の新規プロジェクトに設定します。既存の気象フラッシュカードのSupabase・GitHub設定は変更しません。実装コードとSQLは用意済みですが、実サービスの設定とiPhone・Mac実機検証はまだです。

## 1. Supabaseの専用プロジェクトを作る

1. https://supabase.com/dashboard へログインします。
2. 「New project」を選び、名前を `weather-study-notes` などにします。
3. DBパスワードを生成し、自分のパスワード管理先へ保存します。このチャットやソースコードには貼りません。
4. 利用プランとリージョンを選び、作成が完了するまで待ちます。既存のフラッシュカード用プロジェクトは選ばないでください。

## 2. テーブル・権限・回答保存処理を作る

1. 新規プロジェクトの「SQL Editor」を開き、「New query」を作ります。
2. このプロジェクト内の `supabase/migrations/001_study_sync.sql` を開き、全文をコピーして貼り付け、「Run」を押します。
3. 成功後、別のクエリで `supabase/seed.sql` の全文を実行します。サンプル20問が登録されます。
4. 「Table Editor」で `questions` に20行、`answer_events` と `study_progress` に0行あることを確認します。

最初のSQLは新規環境へ一度だけ実行します。同名テーブルがある場合は削除してやり直さず、エラーを確認してください。途中で失敗した場合はトランザクション全体が戻ります。seedは再実行しても既存IDの問題や学習履歴を変更しません。

RLSはSQLで有効になります。履歴・進捗のSELECTは本人だけに許可され、直接INSERT・UPDATE・DELETEは禁止です。回答は認証済みの `record_answer` RPCだけで追記します。Realtime用のpublicationへの追加もSQLに含まれます。

今回の20問はログイン利用者に共通のサンプル教材です。ブラウザからの問題の追加・変更は許可していません。私有資料の取り込み・所有者別問題集は今後の取り込み段階で追加します。

## 3. メールログインを設定する

1. 「Authentication」→「Sign In / Providers」で「Email」を有効にします。
2. 新規アカウント作成を許可します（初回メールログインでアカウントを作ります）。
3. 「Authentication」→「URL Configuration」に以下を設定します。

ローカル確認中のSite URL：

```text
http://127.0.0.1:5173/
```

Redirect URLsにも同じURLを追加します。開発サーバーに別ポートが表示された場合はそのURLも登録します。メール内のリンクを開くときに開発サーバーが起動している必要があります。

ログインはパスワードを入力しないメールリンク方式です。各端末で同じメールアドレスを入力し、受け取ったリンクをその端末の学習用ブラウザで開きます。リンクは使い回さず、それぞれの端末で新しく発行します。メールテンプレートは初期のConfirmationURL方式を使用します。

Supabase標準のメール配信は、組織のチームメンバーのアドレスに制限されています。最初はSupabase登録に使用した自分のメールアドレスで確認してください。別のアドレスを使う／本格運用する場合は、AuthenticationのSMTP設定で自分のメール配信サービスを接続します。送信制限・迷惑メール・期限切れも確認してください。

## 4. アプリに接続先を設定する

1. Supabaseの「Connect」または「Settings」→「API Keys」から、Project URLとPublishable keyを確認します。
2. プロジェクト直下の `.env.example` を `.env.local` という名前でコピーします。
3. 次の2行を自分の値に置き換えます。

```dotenv
VITE_SUPABASE_URL=https://自分のプロジェクトID.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_自分の公開用キー
```

公開用のpublishable keyを使用します。旧形式のanonキーも対応しています。secretキー・service_roleキー・DBパスワードは絶対に設定しないでください。VITE_の値はビルド時にブラウザ用ファイルへ組み込まれます。公開用キーで守られるのではなく、RLSと認証・RPC権限で本人の履歴を保護します。

4. 起動中の開発サーバーを停止し、ターミナルでこのフォルダに移動して再起動します。

```sh
pnpm dev
```

5. 表示されたURLを開きます。「Supabase未設定」が消え、メールアドレス欄が出れば接続設定が読み込まれています。
6. メールアドレスを入力してログインし、正誤を記録します。「未送信0件」「クラウドと同期済み」を確認します。

.env.localはGitの対象外です。設定変更後は再起動、公開サイトでは再ビルドが必要です。

## 5. 以前の端末内履歴を引き継ぐ

1. 以前と同じブラウザ・同じURL（ホスト名とポートを含む）でログインします。
2. 表示されているメールアドレスが自分のアカウントであることを確認します。
3. 「以前の端末内履歴をこのアカウントへ引き継ぐ」を押します。
4. 未送信が0件になるまで待ちます。

元の端末内履歴は削除しません。同じ回答IDは再引き継ぎ・再送しても二重計上しません。以前の試験操作の履歴も含まれます。別アカウントへの引き継ぎは行わないでください。localhostと127.0.0.1、ローカルとGitHub Pagesは保存先が異なるため、公開URLからローカルの履歴を直接読み出すことはできません。先にローカル側からクラウドへ引き継いでください。

## 6. iPhoneからも開くためGitHub Pagesへ配置する

現在の127.0.0.1はMac自身を指すため、そのままiPhoneで開いても使えません。同期の実機確認には共通のHTTPS公開URLを用意します。

1. GitHubにこのアプリ専用の新規リポジトリを作ります。既存のフラッシュカード用リポジトリは使いません。
2. このフォルダのソースを登録します。.env.local、node_modules、distは登録しません。
3. リポジトリの「Settings」→「Secrets and variables」→「Actions」→「Variables」に以下のRepository variablesを登録します。
   - `VITE_SUPABASE_URL`：Project URL
   - `VITE_SUPABASE_PUBLISHABLE_KEY`：公開用キー
4. 「Settings」→「Pages」→「Source」を「GitHub Actions」にします。
5. 「Actions」→「Publish study site」→「Run workflow」で手動実行します。設定前に勝手に公開されないよう自動公開は設定していません。
6. 完了後、Pagesに表示された公開URLをコピーします。例：`https://ユーザー名.github.io/リポジトリ名/`。
7. SupabaseのURL ConfigurationでSite URLをその公開URLに変更し、Redirect URLsにも同じURLを追加します。ローカルURLも残します。
8. MacとiPhone両方で公開URLを開き、それぞれ同じメールアドレスでログインします。

Viteのbaseは相対パス `./` です。ページ内の画面切り替え方式なので `/リポジトリ名/` 配下でも動作します。認証の戻り先は現在のディレクトリで生成し、リポジトリのパスを保持します。サブページへの直リンクは使用しません。

GitHub Pagesに置くフロントエンドは公開されます。現在のビルドにはサンプル20問を含みます。個人資料や公開できない資料をソースJSONへ追加して公開しないでください。今後の私有教材は認証付きDBへ保存する設計に拡張します。

## 7. 同期の受け入れ確認

1. Macで問題001を「間違い」にします。iPhoneの復習対象へ反映されることを確認します。
2. iPhoneで同じ問題に1回正解し、Macでも復習対象のまま、連続正解1回になることを確認します。
3. Macで正解し、両方で習得済みになることを確認します。
4. iPhoneで間違え、両方が復習対象・連続正解0になることを確認します。
5. ページを開いたまま通信を切り回答します。「未送信」が増えることを確認し、再読み込み後も残るか確認します。再接続して0件になり、他端末にも反映されることを確認します。アプリ本体をオフラインで新規起動するPWA機能は今回の対象外です。
6. 両端末で同じ問題に同時回答し、履歴に2件増え、回答回数も2増えることを確認します。順序は端末の時計ではなくDBがロックを取得した順です。
7. ログアウトして別アカウントでログインし、前のアカウントの履歴が表示されないことを確認します。別アカウントには未送信分も送られません。

Realtime通知で再取得します。通知に問題がある場合も30秒ごとの取得・画面復帰・通信復帰・手動再試行で追いつきます。未送信を含む進捗は暫定で、同期後にサーバー受付順で確定します。

## エラー時

- メールが届かない：組織メンバーのメールか、SMTP、送信制限、迷惑メールを確認します。
- ログイン後に別ページへ戻る：URL Configurationの公開URLを末尾の `/` とリポジトリ名まで確認します。
- テーブル・関数が見つからない：手順2のSQLを正しい新規プロジェクトで実行したか確認します。
- 問題が未登録：seed.sqlを実行します。
- 同期に失敗：画面のエラーを確認し「同期を再試行」を押します。未送信0件になるまでサイトデータを消さないでください。
- セッション期限：同じアカウントへログインし直します。端末内のキューはそのアカウントにだけ紐付いて残ります。
- 端末保存自体に失敗：成功表示せずエラーになります。その場合の回答はまだ永続化できていないため、解消・再試行までページを閉じないでください。
